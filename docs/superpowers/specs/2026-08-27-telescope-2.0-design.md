# Telescope 2.0 — Design

Status: approved 2026-08-27

## Problem

The library works, but its structure dates from 2022 and carries two
correctness bugs that fall directly out of that structure.

**Batch association is broken under concurrency.** `Telescope.setup()`
constructs one instance, and the request middleware assigns
`telescope.batchId = uuidv4()` on every request (`src/api/Telescope.ts:65`).
The field is shared, so when two requests overlap, entries recorded by the
first are stamped with the second's batch id. Grouping entries by request —
the feature the batch id exists for — silently produces wrong results on any
server handling concurrent traffic.

**HTTP client capture pairs the wrong request with the wrong response.**
`ClientRequestWatcher.capture()` stores the in-flight config in a
module-scoped `let request` (`src/api/watchers/ClientRequestWatcher.ts:45`)
written by the request interceptor and read by the response interceptor.
Concurrent axios calls overwrite each other, so recorded entries can show
request A's URL against response B's body.

Both have the same root cause: mutable state shared across concurrent async
work, where request-scoped state is required.

Beyond the bugs, global mutable statics (`DB.driver`,
`RequestWatcher.responseSizeLimit`, `ClientRequestWatcher.ignoreUrls`,
`Telescope.enabledWatchers`) prevent running two instances and leak
configuration between tests; the `/telescope` mount path is hardcoded; asset
resolution string-matches `process.cwd() + '/node_modules/@damianchojnacki/telescope/dist/'`,
which fails under pnpm, Yarn PnP, and monorepos; and `enum` declarations are
non-erasable syntax, blocking Node's native type stripping.

## Prior art: PR #2

Upstream PR #2 (`damianchojnacki/telescope`) proposes two features we want: a
queries collection and a flag to disable the client UI. Its implementation
cannot have worked, and is treated here as a specification rather than as code
to port.

Verified defects in that PR:

- `TypeORMWatcher.entryType` is `WatcherEntryCollectionType.log` and `save()`
  writes to `DB.logs()`. Query entries land in the logs collection; the
  queries screen reads `queries` and stays empty.
- The recorded shape is `{level, data: {query, parameters, args}}`. The
  bundled UI reads `content.sql`, `content.time`, `content.slow`,
  `content.connection`. Every row would render blank.
- `enableClient` is dead: `if (options.enableClient) { ... }` only assigns on
  a truthy value, so `enableClient: false` — the only useful value — is
  ignored.
- Several imports omit the `.js` extension in a `"type": "module"` package,
  which throws at runtime.
- Imports reach into `typeorm/browser/platform/BrowserPlatformTools`, a
  browser-internal path; `AdvancedConsoleLogger` and `InspectOptions` are
  imported unused.
- `typeorm` is added as a hard `dependency`, forcing an ORM on every consumer.
- The module-level `eventEmitter` listener registered in `capture()` is never
  removed, leaking on repeat setup.

We take from it: the `queries`/`query` enum members, `WatcherData.queries`,
and the driver array additions. Those are correct.

## Additional bugs found while designing

- `dist/index.html` hardcodes `window.Telescope.timezone` to
  `"Europe/Warsaw"`. `app.js` calls `moment.tz.setDefault(Telescope.timezone)`,
  so every user outside that zone sees shifted timestamps.
- The client's record/pause button issues
  `POST {basePath}/telescope-api/toggle-recording`. `setUpApi()` never
  registers that route, so the button 404s.
- `src/api/Telescope.ts` imports `fileURLToPath`, `url`, and `resolve` and
  uses none of them — the fix for asset resolution, left unwired.

## Non-goal, confirmed by inspection

The Vue client does **not** need reworking for a configurable mount path. It
already derives everything from a single injected object:

```js
window.Telescope = {"path": "telescope", "timezone": "...", "recording": false};
```

`app.js` computes `basePath` and the Vue Router base from `path`, and every
API call goes through `Telescope.basePath`. The sidebar already contains a
Queries entry routed to `/queries`. The path is fixed only because
`dist/index.html` ships that object as a static literal. Templating it at
serve time is the entire change.

## Design

### Baseline

2.0.0, ESM-only, `engines: {"node": ">=22"}`. ESM-only removes the `uuid`
dependency in favour of `node:crypto` `randomUUID()`. Node 22 is the floor for
reliable `AsyncLocalStorage`, `randomUUID`, and global `fetch`.

### Request-scoped context

An `AsyncLocalStorage<TelescopeContext>` replaces `telescope.batchId`. The
middleware wraps downstream handling in `context.run({batchId: randomUUID()}, next)`;
watchers read the ambient context rather than a shared field. The same
mechanism carries the in-flight axios config, removing the module-scoped
`let request`. Both concurrency bugs close with one construct.

Entries recorded outside any request (startup logs) have no ambient context
and record no batch id, which is correct.

### Instance-scoped configuration

`TelescopeConfig` is resolved once in the constructor and passed explicitly to
watchers. `DB.driver`, `RequestWatcher.responseSizeLimit`,
`ClientRequestWatcher.ignoreUrls`, and `Telescope.enabledWatchers` stop being
static. Watchers become instantiable, configured by construction rather than
by mutation.

### Router mount

`telescope.router()` returns an Express `Router` mounted by the caller at any
prefix, replacing mutation of the passed `app`. `index.html` is served through
a template injecting `path`, a resolved `timezone` (defaulting to the host
zone, not Warsaw), and `recording`, and rewriting the three hardcoded asset
hrefs. `toggle-recording` is implemented, backed by a `recording` flag that
watchers honour.

### Queries and Drizzle

`QueryWatcher` records `{sql, bindings, time, slow, connection}` — the shape
the UI reads — with `slow` derived from a configurable `slowQueryThreshold`
(default 100ms).

Drizzle's `Logger` interface exposes only `logQuery(query, params)`, called
before execution, and so cannot supply duration. `wrapDrizzle(db, telescope)`
therefore proxies query execution to time it. `drizzle-orm` is declared in
`peerDependencies` with `peerDependenciesMeta.optional`, and the integration
is exposed at a separate export path (`@damianchojnacki/telescope/drizzle`) so
the main entry never resolves it.

### Folded-in fixes

`enableClient` gated on `!== undefined`. `resolveDir()` rewritten on
`import.meta.url`. Enums replaced by `const` objects with union types, making
the source erasable-syntax clean.

### Deferred to 2.1

`fetch`/`undici` interception. It adds an independent capture path with its
own failure modes and nothing else here depends on it.

## Testing

The existing 31 tests are the regression net and must stay green throughout.
New coverage, each written before the change it covers:

- Two overlapping requests receive distinct batch ids, and entries recorded
  during each carry the right one. This test must fail against current `main`.
- Concurrent axios calls pair each request with its own response.
- Query capture records the UI's shape, with timing, and `slow` set by
  threshold.
- Mounting at a non-default prefix serves the UI and API correctly.
- `enableClient: false` registers no client routes while watchers still record.
- Two instances hold independent configuration.
